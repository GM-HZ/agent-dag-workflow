# 工作流体验与故障恢复

这一轮冻结了节点、Schema 和运行能力，专门收敛安装后的创作、运行与排障体验。界面和 Agent 不引入 Provider、第二套 DSL 或 Canvas 数据模型；唯一真源仍然是 `WorkflowTemplate`。

当前体验与通用 Core 使用同一份 `1.0.0` 正式协议。发布通过仓库的 1.0 流程完成，不拆分内部小包，也不维护候选协议分支。

## 黄金路径

```text
安装 → 打开工作流 → 示例或 Agent 创建 → 校验 → 试运行 → 检查轨迹 → 保存 → 确认发布
```

- 首次打开提供“可运行示例 / 让 Agent 创建 / 最近草稿”三个入口。
- 左侧只有“流程节点”和“Host Tool”两个用户分类。在 DSH 中 Tool 列表来自当前 Agent scope；其他 Host 通过自己的 Gateway 提供同一目录。自定义节点仍属于通用流程节点，不增加第三套 Provider 心智模型。
- 右侧默认展示名称、结构化参数和输入绑定。依赖、Schema、原始配置与结果契约位于高级配置。
- Agent 创建或更新后只交接草稿 ID、修订和校验结果；Canvas 与 Agent 读取同一份模板。
- 保存、校验、未保存且已校验、发布和连接状态始终可见。发布不可变修订需要明确确认。

## 故障恢复

| 类别 | 用户看到的说明 | 恢复动作 |
| --- | --- | --- |
| Host 重启或连接中断 | 当前内容已保留 | 读操作退避重试，在线或页面重新可见时同步；草稿和运行输入从持久 Store 恢复 |
| 草稿修订冲突 | 草稿已在其他位置更新 | 复制当前 JSON，再重新加载最新修订；不自动覆盖或盲目重试 mutation |
| 权限拒绝 | 当前调用者没有执行权限 | 返回 Host；Authority 与 `spec.requires` 共同收窄权限 |
| 模板或 Schema 错误 | 数据或模板未通过校验 | 打开“问题”，跳转具体节点；不通过放宽 Schema 或依赖绕过 |
| Tool / Agent / 节点失败 | 工作流执行失败 | 底部突出失败原因，图上标出节点；原始技术详情仍可展开审计 |
| 引用不存在 | 草稿、运行、节点或 Tool 不可用 | 刷新目录并检查精确名称和版本 |

Canvas 只自动重试节点目录、草稿目录、读取、校验和轨迹等幂等请求。创建、更新、发布和运行不会因为丢失响应而自动重放，避免重复副作用。

## 运行轨迹

默认轨迹只展示开始、节点状态和最终结果等业务事件，连接与 checkpoint 等底层事件可按需展开。失败信息优先显示“错误类别、失败节点、建议动作”，原始错误保留在技术详情中。选择节点后可查看当前运行的持久化进度和节点输出。

## 质量门禁

提交前运行：

```bash
pnpm check
```

覆盖层次：

- Core：编译、表达式、脚本沙箱、能力裁剪、调度、恢复与结果契约。
- Catalog/SQLite：CAS、diff、发布修订、持久化运行与恢复。
- DSH Host：Tool/Agent/approval 适配、Skill、紧凑 Agent 交接输出。
- Agent Access：CLI v1 Envelope、Skill 按需加载、固定 MCP Gateway 和上下文预算。
- Canvas：授权 RPC、幂等重试、错误分类、本地恢复、首次示例、轨迹投影和生产 bundle。
- 根包：安装 manifest、bundle 装配、Showcase 模板和真实运行 smoke。

浏览器验收还应覆盖明暗主题、首次空画布、草稿恢复、连接中断、冲突提示、失败节点跳转和发布确认。
