# 工作流体验与故障恢复

本文定义稳定版的创作、运行与排障体验。界面和 Agent 不引入 Provider、第二套 DSL 或 Canvas 数据模型；唯一真源始终是 `WorkflowTemplate`。

## 黄金路径

从 DSH 打开 Canvas 首先进入「我的工作流」。首屏会显示当前 DSH 会话、执行身份和存储位置，并列出正在运行、已中断、需要处理或最近结束的 Run。点击记录会打开原 Run ID。收藏的已发布工作流可在首屏运行，启动前显示确切修订。保存和复用上次参数都是显式操作，参数保存在当前设备的会话范围内。

没有工作流时可打开「订单示例」。Canvas 使用与 CLI 相同的内置模板和三笔订单输入，运行后可查看金额合计 `100`，然后修改参数或保存为自己的草稿。高级字段有未完成或无效的 JSON 时，保存、校验、运行和发布会提示定位该字段。关闭前可以选择保留本机草稿或丢弃恢复副本。

```text
安装 → 打开工作流 → 填入参数 → 试运行 → 从运行历史复盘 → 保存并发布可复用版本
```

- 首次打开提供“可运行示例 / 让 Agent 创建 / 最近草稿”三个入口。
- 左侧只有“流程节点”和“Host Tool”两个用户分类。在 DSH 中 Tool 列表来自当前 Agent scope；其他 Host 通过自己的 Gateway 提供同一目录。自定义节点仍属于通用流程节点，不增加第三套 Provider 心智模型。
- 右侧默认展示名称、结构化参数和输入绑定。依赖、Schema、原始配置与结果契约位于高级配置。
- Agent 创建或更新后只交接草稿 ID、修订和校验结果；Canvas 与 Agent 读取同一份模板。
- 保存、校验、未保存且已校验、发布和连接状态始终可见。发布不可变修订需要明确确认。

## 试运行前

从 Canvas 打开入门示例时，运行输入已填好。简单字段可在表单填写，结构化数据可继续使用 JSON。试运行会先检查模板和输入，再检查根流程及固定修订子流程所需的宿主接口和当前会话可见的 Tool。问题面板可定位到根流程节点，子流程诊断附带修订和内部路径。必经路径上的缺失能力会阻止启动。可跳过的分支和无法确定是否有条目的循环只显示警告，已知为空的循环会跳过子流程能力检查。Tool 的实际执行权限由宿主判定。

终端用 `adw demo` 运行包内示例。检查自己的工作流时，可用 `adw validate workflow.json --input input.json` 获取同类诊断。命令和输出说明见 [快速开始](./guide/quickstart.md) 和 [创作与发布](./guide/authoring.md)。

## 故障恢复

| 类别 | 用户看到的说明 | 恢复动作 |
| --- | --- | --- |
| Host 重启或连接中断 | 当前内容已保留 | 恢复连接后同步。已保存草稿从宿主读取，未保存修改可从当前会话的浏览器备份恢复 |
| 草稿修订冲突 | 草稿已在其他位置更新 | 复制当前 JSON，再重新加载最新修订；不自动覆盖或盲目重试 mutation |
| 权限拒绝 | 当前调用者没有执行权限 | 返回 Host；Authority 与 `spec.requires` 共同收窄权限 |
| 模板或 Schema 错误 | 数据或模板未通过校验 | 打开“问题”，跳转具体节点；不通过放宽 Schema 或依赖绕过 |
| Tool / Agent / 节点失败 | 工作流执行失败 | 底部突出失败原因，图上标出节点；原始技术详情仍可展开审计 |
| 引用不存在 | 草稿、运行、节点或 Tool 不可用 | 刷新目录并检查精确名称和版本 |

Canvas 只自动重试节点目录、草稿目录、读取、校验和轨迹等幂等请求。创建、更新、发布和运行不会因为丢失响应而自动重放，避免重复副作用。

## 运行轨迹

默认轨迹只展示开始、节点状态和最终结果等业务事件，连接与 checkpoint 等底层事件可按需展开。失败信息优先显示“错误类别、失败节点、建议动作”，原始错误保留在技术详情中。选择节点后可查看当前运行的持久化进度和节点输出。

在 Canvas 试运行后可直接查看或复制 Run ID 和输出 JSON。用同一个 Run ID 重新打开轨迹时，最终输出从持久化运行结果读取。

“运行历史”可按状态或当前流程筛选，打开较早的运行，展开单条事件并下载完整 JSONL。导出包含浏览时折叠的底层事件。日志不依赖打开着的 Canvas，使用同一会话与 SQLite 数据库即可重新读取。审计与复盘时先从 Run ID 定位，再按修订和 `seq` 核对关键节点。详见 [运行与存储运维](./operations.md)。

试运行和已发布修订启动后会返回 Run ID，可在画布查看增量轨迹或打开运行历史继续检查。旧运行用当时的冻结模板展示节点和已提交结果。若执行中断或暂停，在历史里确认待处理节点后再恢复。日常可把参数保存为浏览器中的个人预设，也可以从历史带入并在下次运行前校验。

## 质量门禁

提交前运行：

```bash
pnpm check
```

覆盖层次：

- Core：编译、表达式、脚本沙箱、能力裁剪、调度、恢复与结果契约。
- Catalog/SQLite：CAS、diff、发布修订、持久化运行与恢复。
- DSH Host：Tool/Agent/approval 适配、Skill、紧凑 Agent 交接输出。
- Agent Access：CLI v1 Envelope、Skill 按需加载、固定 MCP Gateway 和上下文预算。
- Canvas：授权 RPC、幂等重试、错误分类、本地恢复、首次示例、轨迹投影和生产 bundle。
- 根包：安装 manifest、bundle 装配、Showcase 模板和真实运行 smoke。

浏览器验收还应覆盖明暗主题、首次空画布、草稿恢复、连接中断、冲突提示、失败节点跳转和发布确认。

## 个人场景验收

从手工反复执行的固定任务开始。Agent 处理语义判断，模板固定数据契约、运行顺序和副作用边界。用户通过 CLI、MCP 或 DSH 执行同一修订，遇到问题时用 Run ID 查到结果与证据。

| 阶段 | 交付 | 进入下一阶段的验收目标 |
| --- | --- | --- |
| 1. 跑通第一次 | 使用无外部依赖的入门示例，围绕参数、试运行和结果验证。 | 十分钟内完成首次运行，关闭再打开 Canvas 后能从历史找回结果，并导出连续 Journal。 |
| 2. 复用输入和流程 | 用固定修订运行日常整理或个人周报。以明确输入绑定复用同一流程。 | 能从运行历史比较两次结果，并把值得复核的一次导出为回归样本。 |
| 3. 验证重复触发和恢复 | 在已有定时入口演练无效输入、宿主中断和重复投递。 | 记录坏事件的拒绝原因，后续有效事件可以推进，重启后可定位恢复点，外部动作按其幂等契约处理。 |

这些场景可用单进程和 SQLite 完成。DMS、搜索、消息和部署的权限及凭据继续由宿主管理。
